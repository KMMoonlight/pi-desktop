# Native Editor Support

Current acceptance criteria are in [sdk-acceptance.md](sdk-acceptance.md).
The shared renderer and invocation categories referenced as open in older
paragraphs are now integrated. Recorded input/device limitations remain evidence
boundaries; arbitrary third-party editor parity is not a completion requirement.

Working status now uses the original Pi indicator object. It embeds through `CustomEditor.setWorkingStatusIndicator` when `embedWorkingStatus` is true; editors without embedding use the shared native status container. Editor replacement moves the same active object and clears the retired editor's pointer. Working message/visibility/options, retry, first branch summary and compaction transitions retain native implementations and timer cleanup. Grouped source/browser/native results are recorded in `sdk-support.md`; this does not establish full terminal start/stop or redraw accounting.

The default composer now mounts an original SDK `CustomEditor` through the same generic mapping as extension editors. It uses the shared generation TUI, configured keybindings, editor padding, completion height and working-status embedding. Replacing it with an extension editor retains the default instance; restoring it transfers expanded text while keeping its history and configuration. Autocomplete provider replacements reach both the active editor and the retained default. History is initialized once per original default instance. Direct SDK text mutations remain authoritative. Legacy `text`/`selection` transport aliases resolve to current generic controls before normal action validation; obsolete instances and unavailable controls retain their existing guards.

The default custom-editor path runs the original factory and maps `Editor`/`CustomEditor` instances, including subclasses, to a native textarea. Original `handleInput()` overrides and Pi's editing/completion engine remain active. It does not inspect extension source hashes. Terminal-only decorations added by an overridden `render()` are not inferred as desktop elements. See [component mapping](component-mapping.md) for coverage and limits.

Mapped editors retain Pi's large-paste storage. The textarea displays the original compact paste markers, while SDK `getEditorText()`, desktop prompt submission and accepted history use the expanded content. Browser text synchronization and selection replacement preserve unrelated paste bodies. Selection typing, SDK paste and selection deletion each use one original undo snapshot; original change callbacks still run synchronously within input handling. Restoring the default editor transfers expanded text. Desktop range deletion saves paste storage for undo and delegates the final grapheme deletion to Pi, including its marker handling. Registered markers are atomic selection spans using Pi's original segmenter. A collapsible native preview exposes full content, copy and removal with undo; stale preview commands cannot affect replacement paste blocks. Literal marker-looking text remains editable.

Literal text insertion containing newlines, tabs or other control bytes uses Pi's bracketed-paste protocol, including committed composition text. The original input listeners and component handler receive that protocol. This preserves range replacement, logical lines, Pi's line-ending/tab normalization, large-paste storage and a single undo transaction. The default composer now uses the original Pi handler through the generic bridge as well. Browser regressions drive trusted multiline `fill()` and `Input.insertText`, whole/cross-line selection replacement, consecutive insertion, large-paste expansion/undo, original subclass transformations and listener consume/replace in default, custom and dialog editors. CDP composition regressions cover multiline commit/undo; they do not establish real OS IME compatibility. The shared `--input-replacement` native workflow covers these same cases and is included in both full and mapped-component native QA.

Single-line `Input` range replacement/deletion also uses one original undo snapshot. The bridge saves the original value before removing the range, scopes nested snapshot calls during original input handling, and restores the instance's method descriptor on completion/error. Original method replacements are retained. Regressions cover text and multiline/tab insertion, range deletion, undo, exception cleanup and the original submit callback; pasted newlines flatten and tabs expand using Pi's own Input implementation.

Selected Backspace/Delete reaches the original `handleInput()` before the bridge changes text. Consumed keys preserve the native range. Delegated deletion reduces the selected range to one Pi grapheme, then invokes the original deletion method within the same undo transaction. Original change callbacks and deletion overrides remain callable; method replacements and exceptions restore scoped descriptors correctly. Integration/browser workflows verify original handlers, consumed keys, cross-line/Unicode ranges and undo. Native `--input-replacement` includes the same extension subclass checks.

Mapped Input/Editor insertions retain their text and selected range at the DOM event boundary. Provisional text is displayed without generating a second native input/undo transaction; queued requests still run the original Pi handler once. Consecutive insertions rebase through preceding handler results, and the final acknowledgement preserves a newer browser drag selection. Pending insertions suppress stale component snapshots and selection echoes. Actual IME compositions keep their existing commit lifecycle and can refer to the preceding insertion result. The default composer uses this same mapping and original Pi undo engine. Consumed input and unchanged release replies preserve desktop selections, including asynchronous clipboard replacement. Accepted follow-up actions clear the original editor synchronously before emitting activity so their input acknowledgement cannot restore the old draft.

IME compositions keep provisional text local and send only committed text through original component handlers and extension input listeners. Both browser final-input event orders, cancellation, selection replacement, subclass transformations and listener consume/replace are covered. Consecutive commits rebase against the previous handler's actual text. An older acknowledgement cannot reset a newer composition or clear its state. Original Pi undo coalescing remains active. These scenarios pass at desktop/narrow browser widths and in native WebView2. This does not establish compatibility with every real OS IME.

An active composition and a committed composition awaiting its response have separate lifetimes. Ordinary typing and paste after a commit read the acknowledged text and selection inside the input queue, so the original handler's transformation cannot erase subsequent input. The final-input suppression checks the DOM value and retains legitimate repeated input with the same text. Regression coverage includes immediate typing, repeated text, paste and both final-input orders. Chromium CDP also generates composition/input events for commit, cancellation, selection replacement, transformation and undo; its composition-end event is untrusted. Real OS IME remains unverified.

Integration regressions cover expanded reads, synchronization, replacement, undo, callback replacement/error cleanup and submission/history. A shared browser and native WebView2 workflow additionally drives actual desktop selection events, typing, SDK paste, deletion, Ctrl+Z, submission and editor restoration. Browser coverage includes 1440px and 390px widths.

Completion confirmation uses a stable editor command while Pi replaces suggestion-list instances. Native buttons wait for preceding queued keyboard transactions. A confirmation arriving after an earlier Tab has already applied completion does nothing. This prevents unavailable-action notices during rapid typing and confirmation clicks; delayed browser regressions and the focused native `--mapped-completion` workflow verify this behavior.

Default and mapped `Editor`/`CustomEditor` controls measure visual rows and grapheme caret positions with browser DOM ranges using the textarea's actual font, padding and content width. The common bridge supplies that geometry during the original Pi input handler; history, completion, callbacks and atomic paste segments still use Pi's engine. Vertical navigation retains a pixel column across consecutive moves, while paging uses the textarea viewport and preserves Pi's minimum of five rows. Shift selection uses the same browser geometry. Version-dependent instance method access is scoped and restored even when original handlers throw; no Pi prototype or installed source is patched. Browser reference comparisons cover proportional fonts, soft wraps, explicit newlines, Chinese characters, emoji, combining characters, repeated movement, pages and Shift selection in default, custom and dialog editors at 1440px and 390px. These tests initialize text through the authoritative component action and drive navigation with trusted browser keys. Native WebView2 passes the same workflow through `--editor-navigation`. Exact native behavior at document/page boundaries, bidi caret affinity and arbitrary subclass geometry remain separate limits.

Geometry is measured when each queued input executes, with dimensions and styles included in the layout cache. Resize regressions hold an ArrowDown acknowledgement, change between desktop/narrow widths and queue Shift+ArrowDown. The resulting selection matches a native reference textarea in default, custom and dialog editors. Browser and native `--editor-navigation` workflows share this case; it does not establish arbitrary custom layout or bidi behavior.

The remainder of this document covers the older opt-in `modal-editor.ts` presentation and historical controller workflows. The legacy presentation is selected by its source hash only when `legacyExampleAdapters` is enabled. It retains its separate native controller and modal state; the default composer now uses the original SDK `CustomEditor` above.

The browser's textarea supplies presentation, selection and undo. `backend/editor-commands.ts` uses Pi's public `Editor` for command state, history, deletion buffers and character jumps. Its unstarted TUI supplies detached hit-test geometry; rendered strings are discarded. Keybinding managers are installed only around synchronous calls and restored in `finally`. No terminal output is displayed, and installed Pi or extension files are not patched.

## Verified Behavior

| Capability        | Desktop behavior                                                                                                                                                           |
| ----------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Modes             | Insert/normal indicator; Escape enters normal mode; i/a return to insert mode                                                                                              |
| Normal navigation | h/j/k/l, 0, $, x; a advances the caret before insertion                                                                                                                    |
| SDK editor APIs   | Authoritative text reads/writes, selection replacement on paste, text restoration when the default editor is reinstated                                                    |
| Selection         | Native select/selectionchange/input events synchronize text and caret; server caret revisions apply once                                                                   |
| Submission        | SDK-configured submit/newline keys, authoritative text submission, editor clearing after accepted prompts                                                                  |
| Completion        | Actual Pi completion provider, extension command suggestions, configured selection/cancel/Tab keys and explicit completion; choosing a suggestion does not submit a prompt |
| Input             | Ordered extension input listeners and shortcuts before the editor controller; raw paste, beforeinput and composition events reach the same bridge                          |
| Editing           | Native selection, clipboard replacement, deletion, multiline navigation and native undo                                                                                    |
| Pi commands       | Configured cursor/word/line movement and deletion, accumulated kill ring, yank/yank-pop, forward/backward character jumps across Unicode and multiline text                |
| History           | Accepted desktop prompts and current session user messages; previous/next traversal restores the unfinished draft and caret                                                |
| External editor   | Pi settings/`VISUAL`/`EDITOR` command, quoted arguments, temporary prompt file, success/error handling, explicit cancellation and session-replacement cancellation         |
| Control actions   | Interrupt, clear, thinking/model cycling, tool expansion; Ctrl+D deletes when nonempty and requests window close when empty                                                |
| Lifecycle         | Resource reload, session replacement, default editor restoration, unique mount instances and rejection of obsolete actions/input                                           |

Integration tests verify actual SDK loading, original factory identity, configured bindings, raw-input transformations, selection/paste, history drafts, kill accumulation, yank rotation, Unicode jumps and lifecycle. External editor fixtures verify paths with spaces, literal shell characters, failure, cancellation, temporary-file cleanup, session replacement and draft changes even when the text is subsequently restored. Completed external text remains available through `editor.external.result` when a draft conflict prevents automatic application.

Browser workflows exercise desktop and narrow viewports, remapped completion keys, command undo, history, character jumps, an external editor subprocess, synthetic clipboard/beforeinput/composition events, submit/clear and agent abort. Command responses apply text/caret before processing the next queued key, preserving command ordering and browser undo transactions. Applying a backend text transaction updates the native control without sending it back as another user edit or a transient selection change. Transaction revisions prevent delayed text acknowledgements and older snapshots from replacing a later command result; a browser regression test deliberately holds an earlier acknowledgement while executing a deletion command.

The same editor workflow also passes in the packaged Tauri WebView2 application with its bundled Node and Pi SDK. A separate native check confirms that Ctrl+D with an empty editor closes the window and exits the desktop process with code 0.

## Remaining Differences

This is not complete parity with the original `CustomEditor` and terminal editor:

- Application actions include model/session selectors, thinking save/toggle, copy-last-message, follow-up/dequeue and clipboard-image shortcuts. They do not implement terminal-only process suspension.
- Visual-row navigation uses desktop measurements; history and document/page boundaries retain Pi's rules, which may differ from a plain browser textarea. Bidi caret affinity and unusual custom geometry need further validation. Resize during an outstanding navigation acknowledgement has browser/native reference coverage. Default and custom mapped editors retain Pi's paste markers and native previews; SDK reads and submission use expanded text.
- External editors must keep the launched process alive until editing finishes (for example, `code --wait`). The app's xterm.js/PTY panel is a separate path; the external-editor launcher still requires an appropriate GUI or external-terminal command. Cancelling stops the directly launched process; behavior of independently launched GUI processes depends on the editor.
- Native desktop selection/copy/undo conventions are retained. For example, Ctrl+C copies a selection; it clears the editor when the selection is collapsed.
- Synthetic composition events do not prove correct behavior with every real OS input method or mobile keyboard. Complex raw-control transformations also require further validation.
- The legacy hash covers one example presentation. Modified editors built from Pi's standard `Editor`/`CustomEditor` types use the generic bridge, retaining their original input logic with the bridge's documented display limitations.
- The opt-in modal presentation retains the legacy controller. The default composer and generic custom editors use their original Pi controller through the common mapping.

The complete public SDK remains available to native operations. That availability does not remove these desktop behavior gaps.
