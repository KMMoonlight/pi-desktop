# Interactive runtime lifecycle

The desktop host keeps one interactive runtime for a workspace. Pi SDK resource reload and session replacement retire session content while retaining the shared TUI reference, terminal, application containers, default editor, footer and footer provider. The bridge uses Pi 1.0.0's original `createInteractiveTuiReference`; it does not replace SDK exports or modify SDK source.

| Operation                              | Retained                                                                                          | Retired or reapplied                                                                                                                   |
| -------------------------------------- | ------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------- |
| Resource reload                        | Interactive objects, editor history, direct TUI registrations, direct input/debug/color listeners | Extension UI surfaces and context input subscriptions; message/tool/Bash/status/notice state; editor and terminal settings/keybindings |
| New, switch, fork or import session    | Same interactive objects and direct registrations                                                 | Outgoing session content and UI; footer binds the current session; per-session drafts and settings apply                               |
| Workspace replacement                  | Host-level desktop services                                                                       | Entire interactive runtime, direct registrations/listeners/overlays and footer provider                                                |
| Explicit `clearSurfaces()` or shutdown | No interactive ownership                                                                          | Entire interactive runtime and pending factory ownership                                                                               |

`DesktopUIRegistry.resetExtensionSurfaces()` implements ordinary extension reset separately from `clearSurfaces()`. It keeps the `tui:registrations` mapping endpoint so direct registered objects keep their disposal authority and desktop instance. Native tool rows retire; a new Bash row owner replaces the retired owner so late chunks cannot enter the successor session. Footer/provider disposal belongs to workspace teardown.

Direct TUI input listeners retain Pi's live Set behavior, including duplicates and repeated unsubscribe after remove/re-register. `ExtensionUIContext.onTerminalInput` subscriptions are tracked and cleared as in `InteractiveMode`. An old unsubscribe from that context also retains the original Pi behavior if the identical handler is registered again; the original implementation can remove its newer registration while its tracked subscription remains. Differential tests establish this behavior instead of treating ordinary reload as a new TUI generation.

Pi invalidates captured extension `pi`/`ctx` objects on reload and replacement. Keeping a raw TUI reference does not restore those stale SDK contexts. Context-bound dialogs, external editors and asynchronous factory outputs still lose their session authority. A late factory result is disposed and cannot mount over its successor.

Extension reset hides the top native overlay, matching `InteractiveMode.resetExtensionUI()`. Lower direct overlays retain their original handles; restoring the default editor returns input focus to the editor, matching the original `setCustomEditorComponent(undefined)`. Opaque xterm components request focus through their original mouse handler. The bridge does not infer an automatic focus transfer from a terminal surface click.

The retained default editor reloads its original keybindings manager and applies padding/autocomplete settings. Terminal cursor and shrink flags apply from the current settings, and the original footer/provider bind the current session and workspace directory. Editor replacement within a session continues to preserve the retained editor's direct mutations.

Renderer-mode replacement (`regular`/`fullscreen`) now uses Pi's original renderer factory, native scheduler/redraw state and fullscreen layout. Shared components and the terminal reference survive replacement. Direct input hooks stay with the old renderer; context terminal-input subscriptions rebind, matching Pi. Start/stop and fullscreen exit policy execute the original hooks against a desktop drawing backend, keeping raw extension terminal calls on the physical PTY. See [the renderer contract](renderer-modes.md). These categories do not establish full SDK completion; grouped verification and remaining limits are recorded in `sdk-support.md`.
