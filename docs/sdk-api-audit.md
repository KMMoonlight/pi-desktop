## Extension UI Methods

The default runtime uses Pi's original resource-loader bootstrap and original project-trust resolver. Global extensions receive `project_trust` before project settings/extensions/packages are loaded. The first decisive handler wins; undecided/throwing handlers fall through, and errors become runtime diagnostics. Remembered decisions, global default policy, parent-folder choices and session-only choices retain Pi's semantics. Temporary decisions are cached per cwd for this host, and explicit desktop trust changes update that cache. Public runtime `projectTrustContextFactory` values are forwarded unchanged. Default trust dialogs use the host lifetime and handle input independently of any retired session; host shutdown cancels them before project loading can resume. The resolver is version-bound access to the unchanged Pi 1.0.0 module. See the project-trust category in [the support log](sdk-support.md) for current evidence.

## Authentication

Native app/backend communication uses a dedicated authenticated loopback channel, independent of stdout and inherited child-process output. The per-launch credential is removed from the backend environment before extensions load. Raw extension output, subprocess output and JSON-looking logs are forwarded to xterm.js, never interpreted as desktop packets. The retained CLI `--stdio` mode has only JavaScript stdout redirection and is not claimed to isolate raw descriptor writes. See the [transport verification](sdk-support.md) and [terminal support](terminal-compatibility.md).

`auth.login` passes the SDK settings manager's persistent installation ID through `LoginOptions.getDeviceId`. Selection prompts retain original IDs, labels and descriptions; input/secret prompts retain placeholders and secrecy. Provider prompt cancellation and desktop cancellation share an abort signal. Original auth notifications are also forwarded as `activity: auth`, retaining links, expiry and polling metadata. Regression tests exercise prompt-publication cancellation, credential persistence/logout and the unmodified ChatGPT authorization URL followed by cancellation before token exchange. Desktop/narrow browser and native workflows use a local SDK provider fixture; real-account OAuth is still unverified.

The latest export audit retains 458 declaration exports and 156 unchanged runtime exports. See [the SDK support log](sdk-support.md) for current integration counts, browser/native evidence and outstanding gaps. Export identity proves native API availability; the behavior tests cover the documented workflows.

Extension `ctx.shutdown()` waits for native runtime disposal, including the original `session_shutdown` hook, then publishes a graceful shutdown event. Repeated requests share one shutdown path; stale SDK contexts cannot shut down a replacement session, and new desktop actions are rejected once shutdown begins. Stdio flushes the final event before process exit; HTTP ends its event stream and server. The native shell recognizes intentional shutdown, exits normally and suppresses the backend-crash notice. Browser clients stop reconnecting and show a closed state; late snapshots cannot restore the old workspace.

Host disposal also joins overlapping window, SDK and reentrant cleanup requests into one promise, preserving original errors without rerunning hooks. Disposed hosts reject direct reinitialization. Stdio drains notifications and responses published by all joined disposal callbacks before exiting, including SDK shutdown requested from within the original shutdown hook.

Invoked `withSdk` callbacks and running named SDK operations (model requests, autocomplete and bug-report summarization) join the host's existing lifecycle drain. Closing sends their cancellation signals before waiting; their native runtime/session remains available until those callbacks return or reject. Results, functions and original rejection values are retained by direct calls. Nested callbacks that request and await shutdown exclude their own ancestry from the drain while concurrent operations still join. `sdk.run` import preparation stays outside that wait, with cancellation/runtime/session/trust checked before invoking its callback; the admitted callback is tracked by `withSdk`. An operation that ignores cancellation and never settles can prevent normal shutdown. SDK exports and prototypes are unchanged. See the execution-drain category in [the support log](sdk-support.md) for evidence and limits.

Normal native window close defers app termination until the backend finishes original SDK cleanup, rather than truncating hooks at the former three-second deadline. A packaged regression verifies completion of a 4.5-second hook before exit. Cleanup has no normal-window timeout; a hook that never settles can leave the background process running.

Theme regressions cover the reserved system theme, built-ins with `noThemes`, saved initial settings, named persistence, direct-instance changes without persistence, missing-name fallback, native Markdown/select helpers, changed resource files on reload and saved-theme restoration on session replacement. Browser/native workflows verify actual CSS tokens and document appearance. An absent theme setting uses Pi's system theme.

`setTheme(ui.theme)` resolves the host's live proxy to the active theme instance before applying it. This prevents recursive proxy reads and retains direct-instance semantics, including proxies saved before session replacement. Integration and shared browser/native theme workflows exercise this behavior.

The desktop reports its system appearance before initialization and forwards media-query changes to the host. Automatic light/dark settings and named system themes follow those reports; fixed names and direct instances keep their selection. The appearance selector calls the SDK theme API and retains its system value while appearance changes. Named custom themes watch their actual source path, including filenames different from their names. The original Pi JSON validator and loader reject invalid edits; directory watching survives atomic replacement and preserves the last valid theme. Resource reload, selection changes, replacement and disposal cancel old watchers/timers. Settings, trust, packages and configuration actions share the desktop reload lifecycle; project trust regression verifies project-theme activation/removal. Browser and native workflows emulate media-query changes through Chromium; they do not claim physical OS-settings manipulation or a terminal palette query.

Overlay layout uses Pi's original resolver, resolved render widths and measured DOM height with stale-instance/layout guards. Recursive width propagation retains padding, scroll content widths, stack allocation and visibility semantics. Pointer gestures retain independent frontend/backend state per ID; CDP touch workflows verify rejected captures, surviving captured drags and native-input selection guards at both browser widths and in the native component workflow.

Selected Backspace/Delete now reaches the original component input handler before range deletion. Consumed keys retain text/selection; delegated deletion retains original method callbacks and one undo. Integration cases exercise line breaks, Unicode, original deletion overrides, exception cleanup and method replacement; the shared browser/native workflow checks ordinary extension subclasses.

Standard Text/TruncatedText colors and compound decorations are carried as structured text runs. Anser handles SGR state while Pi supplies indexed-color conversion and OSC 8 link parsing. Text/Box background callbacks and Markdown default backgrounds map to DOM styles. Markdown reuses its native token tree and theme renderers to produce semantic blocks, code highlighting, inline ANSI, original source options and LaTeX. Control captions, prompt/placeholder transformations, selection themes, setting descriptions and loader styles share the bridge while retaining original option values and callbacks. Mixed option/placeholder styles, hyperlinks and blink use structured desktop controls; portalled menus retain original surface/instance ownership, keys and callbacks. Status/working messages and string widgets share structured text/link presentation without changing raw SDK values. Regression cases cover resets, palette/RGB colors, original text-update callbacks, reverse styling with inherited desktop colors, inert terminal controls and literal HTML. HTTP/HTTPS, mailto, tel and file links share validation and native opener dispatch. File URLs resolve to host-native paths, and failed launches provide inline retry feedback. Custom application protocols now use shared validation and a native command that independently validates the destination before dispatching to the OS handler. Unsupported terminal-specific forms and file-association verification retain explicit boundaries in sdk-support.md.

## Historical gaps and verification boundaries

The default bridge maps all 17 standard pi-tui component types plus the SDK's `CustomEditor`, `BorderedLoader` and `DynamicBorder`, including composition, without matching extension names or source hashes. Tests exercise ordinary renamed extensions, original callbacks, remapped keys, settings/submenus, completion, scrolling, pointer events, images, lifecycle and renderer reuse. The previous six example presentations remain disabled by default and explicitly enabled for legacy regression coverage. [Component mapping](component-mapping.md) and [editor support](editor-support.md) describe their separate verification boundaries.

- Arbitrary custom container geometry, terminal-only decorations and all physical touch/browser gestures are outside the current completion guarantee. The official overlay layout rules use desktop logical units rather than terminal glyph dimensions. Native form subclasses, ancestor mouse regions/containers, horizontal/shared occurrences, clipped scroll hits and settings handlers run through the shared bridge, with original capture/focus/render decisions and click semantics. Original handler descriptors and layout writes survive synchronous refresh and exceptions. Direct nested TUI overlays use the generic component mapper, including factories that await child input; delayed caret synchronization does not reclaim overlay focus.
- Mapped editor selection typing/paste/deletion, atomic undo, large-paste reads/submission/history and editor restoration have integration/browser/native regression coverage. Paste previews, copy/remove/undo, atomic registered marker boundaries and stale controls have integration/browser/native coverage. IME regressions cover cancellation, both final-input orders, original handlers/listeners, overlapping acknowledgements, immediate ordinary typing/repeated text/paste, and CDP-generated composition/input with an untrusted composition-end event. Visual-row navigation uses browser-measured wrapping and caret geometry in default, custom and dialog editors, with proportional-font, Unicode, repeated movement, paging and Shift-selection browser references. Resizing while a navigation acknowledgement is pending also has native textarea reference coverage. Native QA shares these cases through `--editor-navigation`. Real OS IME/mobile input, bidi caret affinity and custom geometry still need validation.
- Arbitrary render-only character art uses xterm.js, retaining original component input and completion handlers. This preserves a terminal presentation without claiming inferred semantic controls.
- A concrete editor/overlay or key-transformation reproduction can define subsequent targeted work; exhaustive real-extension combinations are not a current completion gate.
- Real-account OAuth/token exchange, paid providers and remote MCP services are not exercised by the local fixtures.

Native SDK availability and desktop behavior are audited separately. These remaining gaps prevent a claim of complete terminal UI parity or automatic compatibility with future Pi versions.

Desktop-hosted `session.reload()` composes the desktop cleanup with the caller's public `beforeSessionStart` hook. It retains the original session instance and delegates to its original reload implementation; SDK exports, prototypes and installed sources remain unchanged. Desktop cleanup runs before the caller hook and extension startup, retaining the editor draft while clearing old surfaces, input listeners, status/widgets, working indicators and custom completion providers. Keybindings, completion commands and themes refresh from the reloaded resources. Caller errors propagate unchanged. The instance method descriptor is restored when the session is retired; a later replacement installed by a custom runtime is not overwritten. `resources.reload` uses this same path.

Hosted `AgentSessionRuntime.setRebindSession()` and `setBeforeSessionInvalidate()` compose caller hooks with the desktop's session binding and cleanup. Setting, replacing or clearing a caller hook retains desktop ownership for all four original session transitions. Desktop binding runs before the caller rebind hook and the SDK's per-operation `withSession` hook. The caller before-invalidate hook runs before desktop cleanup; cleanup still runs if the caller throws. This hook remains synchronous and any returned Promise is not awaited, matching Pi. Rebind invocation captures its caller hook before asynchronous desktop binding, so replacement during binding affects the next invocation. Callers receive the original runtime receiver and their errors retain identity. Retirement detaches host ownership, restores owned setter descriptors and retains the last caller callbacks; later method replacements and frozen methods are respected. See the callback category in [the support log](sdk-support.md) for validation and limitations.

Desktop reload preparation is scoped to both the hosted session and its current lifetime. Keybinding and autocomplete results commit only while that lifetime is current, and obsolete preparation stops after each asynchronous step. Replacement, overlapping reload and disposal regressions pause preparation at the keybinding and autocomplete boundaries, then verify that stale work cannot remount the successor editor, replace its completion provider, change its draft or access a disposed workspace. A hosted reload superseded by another reload, session retirement or disposal rejects with `AbortError` at the next startup-hook boundary, before obsolete extension startup can run. The caller hook is checked both before and after awaiting it. This does not serialize Pi's native reload implementation.
