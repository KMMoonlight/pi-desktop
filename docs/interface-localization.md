# 界面国际化与遗漏复查（2026-10-07）

本轮对应“设置分割线重叠、按钮不统一”“整体检查遗漏”和“补国际化”。
沿用 `DESIGN.application.md`，没有扩大 SDK、平台或第三方扩展的验收范围。

## 确认的遗漏与修复

| 遗漏 | 原因 | 修复 |
| --- | --- | --- |
| JSON 编辑器与工具栏分割线贴合 | 设置复用了通用 `.section-toolbar` 的底边框 | 四处设置工具栏使用独立 `.settings-toolbar`；编辑器前保留 12px 间隔 |
| 设置按钮仍有不同尺寸 | 统一类名传入组件库的 `attributes`，实际按钮没有该类名 | 使用 Button 的正式 `className` 属性；保存、添加、刷新、取消和移除共享 32px 高度、13px 字体和 8px 圆角，按操作角色选择颜色和变体 |
| 端点编辑与其他表单样式不同 | 独立表单皮肤重复定义字段/背景/间距 | 复用 `.integration-form`；保留单独的配置保存、确认和草稿逻辑 |
| 缺少界面语言机制 | 固定文案散落在组件、桌面组件映射和后台提示中 | 类型约束的语言目录、响应式语言状态、动态参数、日期和数字格式 |
| 国际化可能改变原组件关闭标签 | 同一中文词在设置开关和映射按钮中用途不同 | 中文保留映射器原标签，英文按按钮动作翻译；实际关闭回调通过组件流程验收 |

## 使用与覆盖

在“设置 → 外观与显示 → 界面语言”中选择简体中文或 English。
默认为简体中文，偏好保存为本地 `pi.locale`，刷新后保留；切换时不重建
应用、会话或输入区，也不写入 Pi 的全局/项目配置。`html.lang` 同步更新。

`src/i18n.ts` 管理语言状态，`src/locales/en.ts` 有 486 个类型约束的文案项。
源语言键同时构成中文目录，英文目录提供对应翻译，动态文案使用参数插值。
覆盖侧栏、会话/输入区、模型与思考菜单、用量/速率提示、文件和 diff、会话树、
资源、终端操作、所有设置分类、端点/模型编辑、文件夹选择、标准弹窗及
桌面自身生成的通知、验证错误和后台错误。

SDK 宿主生成的对话框标题/选项、通知和组件映射标签带来源标记，前端只翻译
这些固定文案。回调仍收到原始选项值，动作 ID、JSON 字段和命令不随语言变化。
测试特别使用与界面文案相同的第三方中文标题/内容，确认未标记时保留原文。

用户消息、用户设置的会话名称、文件路径、模型/提供商名称、扩展自己提供的
标题/标签/正文和未知服务诊断保留原文。原生操作系统对话框的按钮和系统提示
由操作系统语言决定；桌面提交给它的标题与筛选器已接入语言目录。
