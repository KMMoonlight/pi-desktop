# 空输入框光标偏移

2026-10-15 的反馈：空输入框的光标偶尔比“描述你的任务…”偏高；输入第一个字或让会话开始执行后恢复。Mac 全屏切换曾被怀疑，但用户随后表示不确定，尚不能认定为触发条件。

本次没有稳定复现原截图中的偏移。独立 WebKit、系统 WKWebView、字体变化、输入与清空、点击、撤销以及原生全屏切换均做了对照。正常状态下的选区写入有调用栈记录，但没有捕获故障发生时的选区，不能据此确认根因。

## 显示层处理

空框获得焦点时，用输入框内的装饰元素显示光标，按同一字体、行高和内边距定位，并隐藏此时的原生光标。输入内容后立即使用原生光标。没有往草稿里插入空格或不可见字符，也没有重挂编辑器、重设选区或通过失焦再聚焦刷新。

装饰光标不接收点击，不进入无障碍树；窗口失焦、输入框失焦或输入法开始合成时隐藏。SDK 编辑器的可配置水平内边距和主题文字颜色仍然生效。富文本占位提示沿用已有的原生输入处理。

这是针对空框显示路径的规避处理，不代表已查明偶发问题的触发原因。

## 验证

- Chromium 与 WebKit 的空框显示、焦点与合成状态、窗口尺寸、字体、主题、测高和异步选区回归：10 项通过。
- Chromium 的现有输入法、Mac 编辑快捷键、对话滚动和字体设置回归：13 项通过。
- 系统 WKWebView 的空框截图、原生全屏进入/退出、窗口失焦/恢复检查通过。光标相对输入框的纵向位置保持一致；失焦后装饰光标没有残留。
- TypeScript 检查和生产构建通过。

新增用例位于 `tests/ui/composer-empty-caret.spec.ts`。本机对照截图、选区调用栈和系统 WKWebView 探针保存在忽略的 `.local/caret-investigation/` 目录。自动化的合成事件与系统窗口检查不能替代实际输入法操作；以上记录的是源码修复验证，不包含已安装应用上的升级验证；修复纳入 v0.1.15 发布。
